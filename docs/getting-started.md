# Your first question in Vadhyar

Start with a real project you trust and one small behavior you want to understand. You can read and record evidence without an API key.

## Start the companion

Follow the [installation guide](browser-installation.md), launch with your project's absolute path, and open the printed loopback address. Keep your normal editor and running app beside it.

## Investigate one concrete case

1. In **Project**, find a JavaScript or TypeScript source file. Load a useful range. If the excerpt is incomplete, select another explicit range instead of assuming omitted code.
2. Enter a requirement and a case. For example, a reservation rule and what should happen when the available seat count is zero. Confirm the words match your intended question.
3. In **Predict**, state what you expect and cite the captured condition behind it. Save before observing. The original prediction remains part of the record.
4. Run or observe the concrete case in your own editor, terminal or application. Record the result and method in **Observe**. This is a self-report; clicking Record does not execute the case for you.
5. Make any needed edit in your normal tool and save it. In **Change**, explicitly refresh the selected source. Review the new identity and keep earlier evidence visible.
6. In **Verify**, attach scoped manual evidence or choose and explicitly approve an existing root-package check. A script's process result is separate from your judgment that the requirement was met. Keep uncertain or unmet verdicts honest.
7. Save a reflection and investigate a separate case. Review **Path** and **Notebook**, then export the complete record.

## Read across files

Add up to five displayed ranges to a reading bundle. Inspect the retained text, search captured lines and use source anchors to follow file responsibilities. Static links are limited to the selected source and do not prove runtime flow. Recapture and replace a saved range explicitly when source changes. **Export the bundle before leaving Project**; it is not durable across navigation or restart.

## Keep records safe

Learning records belong to the current browser/profile/origin. A different port or browser does not move them. Export before switching versions or clearing storage. When a save conflicts with another tab, use the review/export controls; do not assume rejected work was persisted. Start an update in a separate installation directory and preserve any other open learner session.

Optional teaching sends only the explicitly reviewed source excerpt after you approve it. It is assistance, not executed evidence. Project commands run trusted repository code without a sandbox. See the [behavior contract](product-logic-contract.md) and [security guide](../SECURITY.md) for the exact boundaries.
